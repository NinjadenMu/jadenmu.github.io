### GRPO is simple, really
There's a lot of resources online about GRPO and other RL methods for reasoning, but I'll give a brief intuitive introduction:
Suppose we want to train a VLM to classify an image $$X$$ with label $$y$$.  In a supervised learning formulation, we might prompt the VLM to output exactly one token corresponding to its predicted label.  The VLM will then output a probability distribution that token, on which we can easily compute a classification loss, allowing us to backpropagate and make our model more likely to output the correct label token in the future.

![Diagram of SFT](/assets/images/grpo/sft.png)

Now, suppose we want the VLM to output some intermediate "thinking" tokens before giving a final answer (with the hope that the thinking tokens will make the final answer more accurate).  We can't use the previous formulation anymore, since we don't have targets for the intermediate thinking tokens - we only know the target token for the final answer.  

One option for getting those intermediate thinking tokens is asking a human expert to write lots of explanations for how to come to a particular final answer.  This is expensive, and we'd much rather automate this.  A reasonable approach is to give a separate VLM the image and the correct final answer, and ask it to generate an explanation for how it might come to the correct answer.  These post-hoc explanations can then serve as targets for the thinking tokens.  There's a disconnect that I think makes this method less effective though, which is that the post-hoc explanations are fundamentally conditioned on information not available to the model at inference time.  

Another reasonable option is rejection sampling - we can sample many responses from a base VLM asked to solve a problem by first generating intermediate reasoning tokens before giving a final answer.  If we get a relatively diverse sample, some of the responses are likely to be correct.  We can then use those correct responses as targets, increasing the probability our model generates correct answers (and the accompanying thinking tokens) in the future.  This solves the disconnect with post-hoc explanations, and we can go one step further by repeating this same process with our newly updated model (which is now slightly better than the base VLM).  Each iteration will then slightly improve our model, and ideally bootstrap to a strong reasoning model.  This idea is actually one of the simplest formulations we can use to incentivize reasoning with RL, called "best-of-n finetuning."
